# Раскатка и права в OnlineConf

Перед обновлением сервиса примените миграции до `000003` включительно через `make onlineconf-migrate-up`.

## Регламенты раскатки

В админке откройте «Регламенты раскатки». Задайте минимум два этапа с возрастающими процентами. Последний этап должен быть 100%. Для всех этапов после первого укажите положительную задержку в секундах.

Включите флаг и откройте его карточку. Выберите регламент, запустите раскатку и подтвердите первый этап. Сервис применяет этап после подтверждения и истечения задержки. Для следующего этапа задержка отсчитывается с момента применения предыдущего. Подтверждение можно выдать заранее. Перед применением сервис ещё раз проверяет права подтвердившего. Изменения регламента действуют для будущих раскаток.

Понижение процента или выключение флага останавливает активный регламент. Смена глобального состояния сбрасывает процент до 0%. Старые флаги сохраняют процент при миграции. Запуск на уже частично раскатанном флаге начинает с первого этапа выше действующего процента.

## Права и группы

- `owner` и `admin` сохраняют глобальный доступ к ключам, регламентам и подтверждению. Владелец выдаёт и отзывает права, управляет группами и глобальными администраторами.
- Пользователь с прямым или унаследованным правом входит в админку с ограниченным доступом (`member`). Права из разных источников суммируются.
- Делегированный пользователь видит скоупы, в которых у него есть хотя бы одно право на скоуп или ключ.
- Создание разрешается на уровне скоупа и типа ключа. Остальные действия можно разрешить для одного ключа или для всех ключей этого типа в скоупе. Подтверждение доступно только для флагов и выдаётся отдельным правом. Для просмотра и подтверждения в карточке нужны оба права.
- Перенос ключа требует права изменения исходного ключа и права создания в целевом скоупе. Удаление группы отзывает её права у участников.

## Административный API

Пути указаны относительно `/api/onlineconf/admin`. Запись требует CSRF-токен.

| Путь | Операции и тело запроса |
| --- | --- |
| `/access` | `GET` возвращает `{ full, grants }`. |
| `/groups`, `/groups/{id}` | `GET` списка, `POST` с `{ name, member_ids }`, `PUT` с `{ name, member_ids, revision }` и `DELETE` по ID. `PUT` задаёт полный состав и возвращает `409`, если с момента чтения кто-то изменил группу. |
| `/grants`, `/grants/{id}` | `GET` списка, `POST` с `action`, одним получателем (`user_id` или `group_id`) и одной целью (`key_id` или `scope_id` вместе с `key_type`), `DELETE` по ID. |
| `/rollout-policies`, `/rollout-policies/{id}` | `GET` списка, `POST` и `PUT` с `{ name, steps: [{ percentage, wait_seconds }] }`, `DELETE` по ID. |
| `/flags/{id}/rollout` | `GET` состояния или `null`, `POST` с `{ policy_id }` для запуска, `PUT` с `{ rollout_percentage }` для ручного понижения. |
| `/flags/{id}/rollout/approve` | `POST` с `{ run_id, step }`. Номер этапа начинается с нуля. |
| `/flags/{id}/rollout/cancel` | `POST` с `{ run_id }`. Текущий процент сохраняется. |
| `/flags/{id}` | `PATCH` заменяет поля флага и сохраняет текущий процент, если глобальное состояние не меняется. Передайте `name`, `scope_id`, `owner_user_id`, `description` и `enabled`. |

Действия `read`, `create`, `update`, `delete` и `approve` проверяются в Backend. Переход по регламенту записывается в историю флага от имени подтвердившего.
